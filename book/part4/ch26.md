# Chapter 26 — Chaos for Agents: Break the AI on Purpose

The most crowd-pleasing chapter in the original playbook was *chaos*: Netflix invented it, SRE adopted it, and the idea is simple — **the only way to know you'll survive a fire is to set a fire you can control.** Chaos engineering is rehearsal dressed as vandalism.

In the AI era, we add a second stage to the fire. Because now there's a *reasoning brain* in the path — and brains fail differently than disks do.

## Chaos, the classic (60-second refresher)

- **Game Days / failure drills:** deliberately break a component (kill a pod, partition the network, fill the disk) in a *controlled window*, observe behavior, find the seatbelt that was missing.
- **The goal is never "cause damage."** The goal is *knowledge*: "we discovered that sidekiq quietly eats the failed-job queue for four hours before anyone notices."
- **Discipline rules:** small blast radius, clean rollback, rehearsed observers, and a post-drill report that becomes (a) a fix ticket and (b) a new runbook if it exposed an unknown.

All of that carries over wholesale. This chapter is the *new* targets.

## Familia: the failure modes that only agents have

An infrastructure chaos tool kills pods and injects latency. An **agent chaos** drill injects the failure modes that a *reasoning* system actually hits. The 2026 recipe book (open-source agent-SRE suites and platform vendors publish fault templates; the shapes are universal):

### 1. Model/provider failures
- **The LLM API goes dark** (throttled, 5xx, regional outage). Question written into the drill: *does the product degrade gracefully or hang politely to death?* Fallback paths (Chapter 23) are the seatbelt on trial.
- **The model degrades quietly** — slowed but "successful" (a sleep-you-into-latency-budget-blowout scenario). Your p95 alerting and token dashboards are the witness.
- **The model lies** — poisoned or adversarial response (wrong-but-confident). Your evals, judges, and *retrieval-recall* alarms are the detectives.

### 2. Reasoning & behavior failures
- **Reasoning loops** — an agent stuck iterating the same goal ("call tool → get error → call again → …"). This is the #1 runaway agent failure and the drill is *mandatory*: max-iteration counters, token budgets, and backpressure are the seatbelt (Chapter 18's "reasoning-loop breaker").
- **Deadlock injection** — two agents waiting on each other's outputs.
- **Contradictory instructions** — a "user" and a "policy" that say opposite things; does the policy win?
- **Tool-call wrongness** — the agent picks the *plausible wrong tool*; does anything catch the mismatch?
- **Escalation failure** — agent *should* escalate (low confidence, policy-adjacent) but charges ahead instead; does the "human-override" gate fire?
- **Prompt injection** — a hostile string arrives inside user data or a retrieved document; does the guardrail hold (Chapter 29)?

### 3. Memory & context failures
- **Context flooding** — a session balloons past the sane window; does compaction trigger, or does it rot into lies?
- **Stale-memory poisoning** — memories/RAG content silently aged; does the freshness gate catch it (Chapter 19)?

Your chaos *engine* composes these as **multi-fault storms** (a provider outage + a loop + a poisoned doc in one drill) because that's the *correlated* ugliness production actually ships.

## The two-layer architecture every chaos drill needs

From the agent-SRE field notes: your drill must operate at **both layers**, and mixing them up is the most common implementation error:

- **Layer A — infrastructure chaos** (kill the pod, partition the network, saturate the disk, throttle the provider API): use your *existing* chaos tooling (Chaos Mesh, Gremlin, Azure Chaos Studio, Litmus…).
- **Layer B — behavior chaos** (inject the prompt-injection, the contradictory instruction, the loop, the tool-call trap): the agent-governance stack's job. B orchestrates the *behavioral* answer while your infra tools own the *physical* blast.

They compose. Neither replaces the other. A drill that only kills a pod and declares "agents are chaos-tested" is a drill that introduced a liar (behavioral) into a healthy room.

## The scoring: resilience as a number

Run the drill twice — baseline (undamaged) and treated (fault injected) — under identical conditions, and calculate the **resilience score**:

```
resilience = (treated success rate ÷ baseline success rate) × 100
```

Score ≥ 90 with `passed=true` → the agent kept ≥90% of its quality under fire. Write the threshold into your *production-readiness* bar: a new agent doesn't promote until its chaos suite passes (this is the "minimal resilience threshold" idea, and it's exactly as bureaucratic and valuable as it sounds).

Frequently, the *real* prize is the **divergence analysis**: replay real production traces against a *proposed* policy or prompt change before rollout, and count how many actions would have been blocked/failed/budget-damaged *before* a single user met it. Chaos-adjacent, chaos-shaped, and the most-used feature in 2026 agent-governance tooling — policy changes stop being guesswork and become measurement.

## The drill-runner checklist (2026, portable)

```
CHOOSE    – one agent, one scope, real environment (staging ≥ prod)
DECLARE   – hypotheses printed before you break: "I predict X"
INJECT    – infra fault (existing chaos tool) + behavioral fault (governance stack)
OBSERVE   – golden signals + judgment signals + token telemetry, full trace
SCORE     – resilience % vs baseline; passed? 
REPORT    – seatbelt found = bug; unknown = runbook; repeat for the top-3 risks
GUARD     – human-approval path rehearsed: an agent that "chaos-affirmed" but
            needs a human to stop a real loop is a drill that lied to you
```

## The two moods of this chapter

**To the human:** the point of breaking the machine is to make you *calm*. You cannot rehearse everything, but you can rehearse the top-3 blast-radius risks per agent, and calm is a rust-able habit that only drills produce.

**To the machine:** if your AI SRE team has replaced the "hero knows everything" with "we measured who breaks how," you have converted fog into engineering. Chaos is how you prove the guards work *before* the customer finds the hole.
