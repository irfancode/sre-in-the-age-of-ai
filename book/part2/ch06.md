# Chapter 6 — Toil: The Soul-Sucking Work AI Should Eat

## What is toil? (The definition that matters)

Toil isn't just "work." Toil is a specific, diagnosable kind of work, and the original book defined it so well it's worth keeping verbatim in spirit:

> **Toil is the kind of work tied to running a production service that tends to be manual, repetitive, automatable, tactical, devoid of enduring value, and that scales linearly with service growth.**

Five symptoms. If a task has *most* of them, it's toil:

1. **Manual** — a human pushes the button. Every time.
2. **Repetitive** — the same task again and again.
3. **Automatable** — a machine could do it identically (or in 2026: the task is *so well-specified* that even a modest agent could run it).
4. **Tactical** — reactive, scrambly, no strategic gain. It doesn't make tomorrow better.
5. **Devoid of enduring value** — you do it, a week later you must do it again. Nothing compound-pays interest.

Destroying toil isn't laziness; it's **the engine of career growth** — because every hour of toil you eliminate is an hour that returns as compounding engineering time. The classic rule: if you find yourself doing the same manual task *twice*, automate it. Once it's automated, automate the *repair* of the automation. SREs want systems that are **automatic, not just automated** — self-running, self-repairing, self-*improving*.

## The 2026 update: AI is the biggest toil-eater ever invented…

The classic enemies of toil — Terraform instead of clicking consoles, Kubernetes instead of rebooting boxes, CI/CD instead of the sacred manual deploy ritual — remain. But the 2020s added a machine that eats *cognitive* toil:

| Toil you used to do | The 2026 machine that eats it |
|---|---|
| Grep through 20 GB of logs by hand | An AI SRE agent correlates logs, traces, and metrics in minutes |
| Re-type the same runbook update after every incident | An agent drafts runbook improvements from incident usage (Google's SRE AI already does this) |
| Triage 50 alerts a week, 95% of them noise | Alert grouping/prioritization agents fold the 95% into one incident |
| Hand-write the postmortem | An agent produces a structured draft; you review |
| Investigate "why did SRE reports slow down?" | First-responder agent arrives with a dossier, not a bare page |
| Update dependencies / changelogs / docs | Coding + doc agents draft the diffs, you review |

Same playbook as always — *eliminate the human step, keep the human accountable* — but the "automation" got qualitatively smarter.

## …and the biggest toil-maker ever invented. Watch out.

Here's the twist nobody sees coming. The **verification tax** is real: AI generates actions, and *someone has to check them*. The 2025 State of Incident Management data showed **average toil rising from ~25% to ~30%** in organizations that adopted AI agents *without removing the corresponding manual processes*. You didn't replace humans with agents; you added a layer that generates *unreviewed sludge* that humans now review.

Symptoms of the toil tax, in the wild:
- Your team reviews 40 AI-generated PRs a day, each slower to check than a human's would be.
- An "AI SRE" files 60 incidents a day; a human now triages incident-triage.
- ML update cycles generating endless tiny model/config changes, each demanding review sign-off.
- Prompt tweaks and eval updates becoming a never-ending commit pipeline.

**How to dodge the tax (the 2026 toil-elimination playbook):**
1. **Automate the verification too.** If agent output requires review, make review *verification-lite*: auto-lint, auto-test, policy-check, diff-summaries, and "approve-with-evidence" buttons that show exactly what changed. Human review of full diff → human review of a good summary.
2. **Instrument agent decisions** so checks run on *structure* (types, policies, budgets) rather than eyeballs.
3. **Go on a diet.** If your AI pipeline produces more pending-approval noise than your old process produced output, the pipeline is the disease, not the cure. Pareto-trim it.
4. **Enforce the 50% rule** on the AI stack too: if your agents' outputs consume >50% of your team's *review* time, you're not running an automation stack — you're running a work generator.

## The toil ledger: measure it or it will hide from you

What gets managed gets measured, and toil is champion at hiding in meeting-room shame. Build a simple weekly ledger: category — *type / hours / can-it-go-away / who-owns-the-fix*. Categories to keep an eye on: tickets, manual deploys, babysitting, config churn, agent-output review, logging archaeology. A healthy target: your ledger's biggest categories are the ones you're *killing*.

**The 2026 special ledger rows** for agent-heavy teams:
- Reviewer-hours per AI change (the verification tax, counted honestly).
- Agent "pending human" queue depth (is Escalation Station the real customer of the system?).
- Human override rate on agent judgments (a *leading* indicator — see Chapter 24).
- Token spend per automated function (cost is a reliability signal, Chapter 25).

## Toil vs. "good work": a cheat sheet

| Toil | Not toil |
|---|---|
| Restart the same service for the third time | Design the self-restarting service |
| Manually apply a config you could version | Build the Terraform/IaC module so nobody applies configs |
| Review 40 AI PRs worth of undifferentiated sludge | Design the verification-lite pipeline that collapses it to 4 |
| Investigate "is it on fire?" bare | Build the dashboard/agent that answers first |
| Explain the same outage three times | Write the postmortem *and* the auto-response |

Rule of thumb, unchanged at heart: **if you're doing a task a second time, you're failing the first time.**

## Rout you can act on this week

1. **No-click annoyances:** make a list of every "I do this by hand" moment for 5 days. Night-mares > dreams.
2. **Charge them:** weekly 20-minute "toil audit" where each entry gets a verdict: *automate, delegate to an agent (with gates), or accept* (say it out loud, consciously).
3. **Slush fund:** everyone on the team owns a standing "toil kill" task — like tech-debt day, but surgical.
4. **Watch both directions:** track toil eliminated *and* toil generated (verification tax) — two columns, one ledger.
